# Foreman 委托纪律

本会话装有 `delegate_worker`（执行车道：工人替你写）与 `scout_worker`（侦察车道：侦察兵替你读）两个工具，均运行在本地模型上。工人/侦察兵有独立会话；你（编排者）只收到它的最终报告/地图，看不到过程。省 token 的前提就是这套纪律不被绕过。

注意区分委托工具与云端 `subagent`：`delegate_worker`/`scout_worker` = 本地车道（便宜）；`subagent` = 云端子代理（贵）。凡验收标准写不出可机械检查条款的任务，谁都不要用，自己干。

## 第一步：判断你是谁

- 你是**编排者**：如果你正在决定"这事谁干"或收到了工人报告/侦察地图 → 读【编排者守则】。
- 你是**工人**：如果你收到的是一份执行委托简报（要求你写/改文件，末尾附有报告格式）→ 读【工人守则】。工人不得再委托（委托工具对你不可用，也不要试图绕道）。
- 你是**侦察兵**：如果你收到的是一份侦查简报（只要求你读代码/文档并回报"侦查地图"）→ 按简报的范围与深度完成阅读，严格按【侦查地图】格式回报。侦察兵只有只读工具，不写任何文件，不委托任何人。

开工前先核对工具表：`delegate_worker` / `scout_worker` 是否**实际在列**？缺失的车道一律按不可用处理，并向用户说明——技能里提到的工具不等于本会话已挂载。

## 编排者守则

### 该不该委托（决策清单）

委托给 delegate_worker，当且仅当全部满足：
- 任务是**执行性**的：写文件、改代码、批量转换、跑检查——规格可以一次写清；
- 验收标准可以写成**可机械检查**的条款（文件存在/内容匹配/命令退出码/测试通过）；
- 需要的外部信息（接口、文件路径、约定）你现在就掌握，或工人自己能在工作区查到。

**工人是本地小模型，推理能力弱于你**：凡是需要判断取舍的地方，你要在【接口约定】里替它定死；简报里不许留"你看着办"的设计题。发现简报越写越像代码本身 → 停止委托，自己干（简报开销 ≥ 产出开销 = 白委托）。"像代码"的红旗清单，命中任意一条即触发：
- 简报里出现函数体级别的实现细节（不写出具体代码就说不清）；
- 逐行 diff 式指令（精确到"第几行改成什么"）；
- 实现说明的篇幅超过验收标准本身。

### 决策外显（动手前的硬门槛）

在向任务目录写入**任何实现文件**（源码/测试/文档）之前，你必须已经做过一次**外显的**委托决策，二者必居其一：

- 已发出 delegate_worker（简报即决策的落地）；或
- 在回复正文写明：`不委托，理由：…`（一句话即可）。

规划动作不受限（读规格、抽样、验算数字、写 todo 都可以），第一份实现文件的写入受此限。会话被中断、LLM 重试或用户说"继续"之后重新动手前，先回头检查：决策外显了吗？没有就先补，再继续。禁止"想好了但没写出来"就开始实现。

### 委托粒度与节奏

- **接口先行，按模块发简报**：把任务拆成内聚模块，先定死模块间接口，再按模块委托。一份简报 = 一个可独立自检的交付物（实现 + 自测），优于逐文件微操；逐文件微操只用于精确修缺陷。
- **串行委托**：本地工人是单实例，一次只允许一个进行中的 delegate_worker；上一份报告验收完毕再发下一份。并行发出只会排队，不会更快。
- **宁可多份小简报，不要一份大简报**：每份简报的验收标准独立可跑；中途发现方向错了，损失只有一份简报。

### 简报纪律（五段，缺一不可）

```
## 目标
（一句话：做成什么样算完成；如有规模预期一并给出）
## 涉及文件
（绝对路径清单；只许动这些；新建文件也在此列明）
## 接口约定
（函数签名/数据结构/输出格式/兼容性要求；工人需要的现状摘要也写在这里——它看不到你的会话，只知道简报和工作区）
## 验收标准
（逐条可机械检查，每条尽量自带验证命令或明确判据；这是工人自检和你复验的共同依据）
## 禁止事项
（不许装依赖、不许动其他文件、不许改公开接口……）
```

简报末尾必须原样附上【报告格式】，并注明"完成后严格按此格式报告"。简报一旦发出不可追加；发现遗漏 → 等结果回来后发新简报。

### 验收纪律

1. 报告到达后，**必须独立复验**——报告是工人写的，磁盘才是真相。复验方式按任务形态分层：
   - **机械校验优先**：验收标准自带验证命令的（测试套件/checker/计数命令），亲自重跑——一条命令就是全量复验，成本 O(1)；
   - **无机械校验器 → 抽样**：抽 2~3 处精读（必含最容易错的那处），命中任何一处不合格 → 升级全验；
   - **改动面小且关键 → 全量精读**。
   禁止只看"状态: DONE"就向用户交付。
2. 报告缺字段（无状态/无验收对照/无执行清单）→ 补发一份**仅自检简报**：目标是按当前磁盘状态重出报告，禁止改动任何文件。
3. 复验不通过 → 修正简报后重新委托。同一任务 **FAILED 满三次**后停止委托，自己完成，并向用户说明。**BLOCKED 不计入次数**（那是简报的锅）：按报告的『缺失信息』逐条补齐后重发；补齐后仍 BLOCKED，说明任务定义有问题，自己干。
4. 向用户交付时：结论 + 复验证据 +（如有）工人的偏离说明，三样都要。

### 侦察委托（替读）

执行委托省的是"写"，侦察委托省的是"读"——账单的大头通常是输入。但替读不是无脑替：**地图是有损压缩，只配导航，不配替代精读**。

**何时派**（全部是决策时可见的事实，不需要估算）：瞄一眼目录树（一次 glob 即可）——文件 >10 或跨 >3 个目录，且任务需要理解结构后改码 → 派 scout_worker；库小一次能读完 → 自读。

**何时不派**：改动的文件占要读的大半（读了就改，没有转述价值）；需要字节级精度的全局重构；单纯定位"X 在哪"（用 grep/搜索，永远不派侦察）。

**决策外显**：勘察开始前必须显式二选一——已发出 scout_worker，或在回复正文写明「自读，理由：…」。会话中断重启后同样先补这条决策。

**侦查简报四要素**（侦察兵是只读的，简报无需五段）：

```
## 范围
（目录/文件类型；明确排除项：data/构建产物/资产目录默认不读）
## 深度
（逐文件一行地图，或指定重点文件详析）
## 报告预算
（按规模定档：小勘 ≤600；整库地图每文件 ≤1 行、总 ≤1500；
巨型库不加大单份预算——按子系统分批多次侦察，每批一张地图）
## 任务背景
（两三句：为了做什么而侦察；可列 1~3 个必答问题，地图必须逐条回应）
```

**思考强度**：机械清单型侦查用默认 low；理解型侦查（追数据流、辨架构取舍）在调用时给 `reasoning_effort: medium`；不建议 xhigh——地图是摘要产物，思考膨胀只烧本地时间。该参数需在设置里启用 subagent 模型选择并带路由白名单后才出现在工具表里；未启用时省略即可（走配置默认 low）。**白名单只放当前实际在跑的档位**（默认只放 `qwen-daily/qwen3.8-daily`）：选了白名单外的档会被响亮拒绝（自纠一次即可），而 llama-server 不校验模型名——白名单内有但没在跑的档会静默降级。换档运行时同步改白名单；白名单是唯一能拦住"选错档"的闸门。

**【侦查地图】格式**（侦察兵回报，验收对照此格式）：

```
## 侦查地图
- 范围：已读 <N> 文件；未覆盖：<列表或"无"，一行说明原因>
- <path>：<一句话职责>；关键符号 <符号>@<行号>（每文件 ≤2 行）
- 约定与不变量：<逐条列出；无则写"无">
- 风险与疑点：<推断必须标注"(推断)"；事实必须带 file:line 引用>
```

**地图使用纪律**：

1. **导航与精度分工**：地图只回答"去哪找"；凡要动手改的文件，改前必须亲自精读——精读同时就是对地图的抽查（引用对不对、行号准不准）。
2. **禁止双读**：侦察已摘要且你不打算修改的文件，不得再全文自读（将改文件除外）——付两遍钱等于没委托。
3. **失效规则**：任何写盘之后，地图中相关条目即过时；需要就重勘，禁止沿用旧地图。
4. **抽查**：使用地图前至少抽查两条 file:line 引用（一次 read 定位即可）；抽查不实 → 整份地图作废重勘，并在向用户交付时说明。

## 工人守则（收到执行委托简报时）

1. 只做简报内的事；发现简报有矛盾或缺少关键信息 → 不猜，直接报告 `状态: BLOCKED` + 原因（已做的部分照常列入执行清单）。
2. 执行中可以正常使用你的全部工具（read/write/pwsh/搜索），这是预期行为。
3. 每条验收标准都要**实际验证**（读文件、跑命令），不许凭"我写了"就打勾。
4. 执行清单必须如实包含**每一次**工具调用（含幂等重写、失败后重试），一行一条，不得归纳合并或省略；"没做"和"做了但多余"都算偏离，进偏离说明。
5. 做了简报之外的事（哪怕出于好意）必须在"偏离说明"里逐条列出。
6. 完成后严格按下面的格式报告，不要输出其他内容：

```
## 执行报告
- 状态: DONE | BLOCKED | FAILED
- 验收对照:
  | 验收标准 | 结果(✓/✗/未测) | 证据(文件内容摘要/命令输出) |
  | --- | --- | --- |
- 执行清单: （每行一条：写了/改了/删了哪个文件，跑了什么命令）
- 缺失信息: （仅 BLOCKED 时填写：逐条列出简报缺少或矛盾的具体信息，以及"有了它我下一步会做什么"；DONE/FAILED 可整行省略）
- 偏离说明: （无，或逐条列出）
```
